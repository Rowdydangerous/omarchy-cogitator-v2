# Domain docs

This is a single-context project.

## Before exploring

- Read GLOSSARY.md at the repository root when present.
- Read relevant decisions under docs/adr/ when present.
- If either is absent, proceed without creating placeholder documents.
  Domain-modeling work creates them when terms or decisions are resolved.

Existing architecture and lifecycle references are docs/architecture.md
and docs/suite-switching.md. Consult the relevant feature documentation
under docs/ for the area being changed.

## Vocabulary and decisions

Use glossary terms consistently in code discussions, issues, and tests.
When a needed term is missing, identify the gap for domain-modeling work.

If a proposal conflicts with an ADR, cite the decision and explain why
reopening it is warranted rather than silently overriding it.
